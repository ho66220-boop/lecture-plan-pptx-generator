# 운영 가이드 — 배포·리포트 코드·장애 대처

## 1. 배포 사본(Colab 업로드용) 갱신 절차

이 저장소(공개, 더미 데이터)와 별도로, 실제 운영은 **배포 사본 폴더**를 드라이브에 올려 Colab에서 실행합니다.
코드를 고치면 배포 사본을 다음 규칙으로 동기합니다:

| 대상 | 규칙 |
|---|---|
| `src/*.py` | **파일 통째 복사**(양쪽 100% 동일해야 함 — 새 파일 추가 시 누락 주의) |
| `config/defaults.py` | **통째 복사 금지.** 배포본은 수강료 예외(`FEE_PER_SESSION_OVERRIDES` 등)를 실제 강사·단가로 덮어쓴 분기 파일이다. 단가 외 항목(예: `SKIP_SHEET_KEYWORDS`)을 바꿨다면 **해당 라인만** 배포본에 반영하고, 단가 항목이 유지됐는지 diff로 확인 |
| `templates/`·`input/` 양식 | 변경 시 복사 |
| `tests/`·`.github/`·`audit/`·`docs/` | 배포본에 **없음**(복사하지 않음 — 배포본은 실행 전용) |

**동기 후 스모크(매번):** 배포 사본 폴더에서 ① 변경 모듈 import, ② 미니 입력 1건 실행, ③ `config` 분기 유지 diff — 셋 다 통과해야 완료.
[운영자 확인 필요] 드라이브 업로드 방식(폴더 통째 교체 vs src만 갈아끼움)은 운영자 관행에 따름.

## 2. issue_code 카탈로그 (전 23종 — 코드에서 추출)

severity 우선순위: **오류**(산출 누락/실패 — 반드시 처리) > **확인필요**(사람 판단) > **경고**(참고) > **정보**.

| 코드 | severity | 의미 · 발동 조건 | 조치 |
|---|---|---|---|
| `FILE_READ_FAILED` | 오류 | 입력 엑셀을 열 수 없음(손상·암호) — 그 파일만 건너뜀 | 파일 재저장(.xlsx) 후 재실행 |
| `PROGRESS_HEADER_NOT_FOUND` | 오류 | 진도표 헤더 행(5칸 중 4칸 일치)을 못 찾음 — 회차·수강료 미계산 | 헤더 5칸을 양식과 맞춤 |
| `DATE_PARSE_FAILED` | 오류 | 진도 날짜 해석 실패(그 행 회차 제외) | `7/20(월)`·`2026-07-20` 형식으로 수정 |
| `PROGRESS_DATE_MISSING` | 오류 | 내용은 있는데 날짜가 빈 진도 행(셀 병합 소거 등) — 회차 제외됨 | 행마다 날짜 개별 입력 후 재실행 |
| `LECTURE_NORMALIZE_FAILED` | 오류 | 한 강좌 정규화 중 예상 밖 예외 — 그 강좌만 건너뜀 | 해당 시트 입력값 확인 후 재실행 |
| `PPTX_GENERATION_FAILED` | 오류 | 한 강좌 슬라이드 생성 중 예상 밖 예외 — 그 슬라이드만 없음 | 해당 강좌 입력 확인 후 재실행 |
| `OUTPUT_SAVE_FAILED` | 오류 | PPTX 저장이 기본명·대체명 모두 실패(파일 잠금 등) | 열려 있는 산출 파일 닫고 재실행 |
| `BILLING_UNDETERMINED` | 확인필요 | 구분·시즌 모두 공백 → 월 단위 청구로 가정됨 | 특강이면 구분/시즌 입력(전체 합계 청구) |
| `OUT_OF_ORDER_DATE` | 확인필요 | 진도 날짜가 앞 행보다 이전 달(12→1 연도 경계 제외) — 값은 그대로 | 보강이면 무시 가능, 해 넘김이면 연도 명시 |
| `REQUIRED_FIELD_EMPTY` | 확인필요 | 필수 필드(메인 제목·과목·강사명·강좌명) 공백 | 시트에 입력 |
| `REQUIRED_PROGRESS_EMPTY` | 확인필요 | 진도표가 비어 있음 | 진도 행 입력 |
| `A4_OVERFLOW` | 확인필요 | 본문을 하한 폰트까지 줄여도 A4 초과(자르지 않음) | 강사에게 분량 축소 요청 |
| `TITLE_OVERFLOW` | 확인필요 | 제목이 폰트 하한(14pt)에서도 2줄 초과 — 겹침 가능 | 해당 슬라이드 우선 검수, 강좌명 축약 |
| `UNMAPPED_PLACEHOLDER` | 확인필요 | 템플릿 `{{키}}`가 치환 map에 없음(실행당 키당 1회) | TEMPLATE_GUIDE 1절 표와 대조·수정 |
| `TEACHER_PHOTO_NOT_FOUND` | 확인필요 | 강사 사진 미삽입(파일 없음 또는 사진박스 미식별) | 파일명(강사명) 확인, 있으면 템플릿 박스 위치 확인 |
| `TEACHER_PHOTO_INSERT_FAILED` | 확인필요 | 사진 파일이 손상·0바이트라 삽입 실패 | 파일 교체 |
| `FEE_TABLE_MISSING` | 확인필요 | 강의형태에 맞는 단가 설정 없음(수강료 공백) | `config` FEE_TABLE 확인 |
| `OPENING_TIME_PARSE_FAILED` | 확인필요 | 수업 시간에서 시작 시간 추출 실패(개강일에 시간 미표기) | PPTX에서 수동 확인 |
| `SESSION_TYPE_REVIEW_NEEDED` | 확인필요 | 진도 행에 보강/대체 등 키워드 — 회차 포함 여부 확인 필요 | 교무팀 판단 |
| `ACADEMIC_CALENDAR_CONFLICT` | 확인필요 | 수업일이 학사일정과 겹침 | 일정 확인 |
| `WEEKDAY_MISMATCH` | 경고 | 입력 요일 표기 ≠ 실제 요일 | 날짜/요일 확인 |
| `TEXT_LIMIT_EXCEEDED` | 경고 | 권장 글자 수 초과(폰트 축소·확장으로 처리됨) | 필요 시 축약 |
| `PROGRESS_OVERFLOW` | 경고 | 진도 10개 초과 — PPTX에는 10개까지만 | 초과분 수동 반영 or 분할 |
| `CALENDAR_READ_FAILED` | 경고 | 학사일정 CSV 읽기 실패 — 충돌 검사만 건너뜀 | CSV 인코딩(UTF-8)·형식 확인 |
| `NO_LECTURES` | 정보 | 처리할 강좌 시트가 없음 | 입력 확인 |

> 참고: `normalized_data`의 **flags 컬럼**은 위 리포트 코드와 별개의 강좌 단위 표식입니다
> (`WEEKDAY_MISMATCH`·`SESSION_TYPE_REVIEW_NEEDED`·`ACADEMIC_CALENDAR_CONFLICT`처럼 리포트와 병행되는 것 외에,
> `OPENING_TIME_REVIEW_NEEDED`는 flags에만 기록됩니다 — 상세는 같은 강좌의 `OPENING_TIME_PARSE_FAILED` 리포트 행 참조).

## 3. 장애·이상 시 대처

**산출 파일이 열려 있을 때(가장 흔함):**
- 엑셀 산출물(normalized_data·validation_report)이 잠겨 있으면 자동으로 `_재시도HHMMSS`가 붙은 **대체명으로 저장**하고 계속 진행합니다. 대체명마저 실패하면 "파일을 닫고 재실행" 안내와 함께 중단됩니다.
- PPTX가 잠겨 있으면 대체명 재시도 후, 그래도 실패하면 **크래시 없이** `OUTPUT_SAVE_FAILED` 리포트만 남기고 나머지 산출물은 정상 생성됩니다.

**강좌 단위 실패(`LECTURE_NORMALIZE_FAILED` / `PPTX_GENERATION_FAILED`):**
- 배치는 죽지 않고 그 강좌만 빠집니다. 리포트 행의 `source_file`/`source_sheet`/`message`(예외 타입 포함)로 원인 시트를 특정 → 입력값을 고치고 재실행. 반복되면 message의 예외 타입을 개발 담당에게 전달.

**전체 즉시 실패(의도된 것):**
- 마스터 템플릿 부재/손상/슬라이드·레이아웃 0장 → 명확한 메시지로 즉시 중단. 템플릿 경로·파일을 확인.
- 어떤 예외 경로에서도 `validation_report.xlsx`는 그 시점까지 수집된 내용으로 **항상 저장**됩니다 — 실패 원인 추적은 이 파일부터.

## 4. 산출물 파일명 정책 (덮어쓰기 고지)

- `normalized_data.xlsx/.json`·`validation_report.xlsx`는 **고정 이름** — 재실행하면 덮어씁니다(교무팀이 항상 같은 이름을 찾는 UX 우선). 이전 실행분을 남기려면 실행 전 복사해 두세요.
- PPTX는 `강의계획서_초안_YYYYMMDD_HHMMSS.pptx`(초 단위) — 재실행해도 덮어쓰지 않고 새 파일이 생깁니다. 월별 계획서는 `..._{연}_{월}_...`이 추가로 붙습니다.

## 5. 보관 자료 취급

- 로컬 보관 폴더의 자료(과거 히스토리 백업 번들, 실데이터 입력, 실사진 등)는 **어떤 공개 위치(공개 저장소·공유 드라이브 링크 등)로도 이동 금지**입니다. 이 저장소가 공개인 이유는 개인정보를 전부 배제했기 때문이며, 그 경계는 보관 자료 앞에서 끝납니다.
- 같은 이유로 코드 감사 문서(`audit/`)는 `.gitignore`로 로컬 전용입니다 — 커밋에 포함하지 마세요.
